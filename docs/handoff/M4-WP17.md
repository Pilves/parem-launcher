Typing a setting's name in the drawer (3+ characters, e.g. "keyboard") shows a "Settings ›" line; a tap, or Enter when no app matches, opens Settings scrolled to that row.
Contract: `ui/settings/SettingsSearchIndex.ROWS` maps string resources to the view id to scroll to (the row's value view, or the row itself); `SettingsSearch.match(query, rows)` picks one `Row(title, anchor)`; `OmniboxMode.Setting(title, anchor)` is the last mode before `None`; the target travels as nav arg `Constants.SETTING` and `SettingsFragment` scrolls to it.
Not verified: that every settings row is findable by its title on a device (the roadmap's done criterion).
Easy to get wrong: the index is hand-maintained — `SettingsSearchIndexTest` fails when a row title in `fragment_settings.xml` is missing from it, so a new settings row needs an index entry or the test goes red.
