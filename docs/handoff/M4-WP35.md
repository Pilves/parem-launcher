Every settings row is one spoken node: the container is screenReaderFocusable with the label as contentDescription and is the click target, label and value children are importantForAccessibility=no, binary rows get a Switch role plus on/off state and picker rows their value as state through ui/settings/SettingsRowAccessibility.kt; section titles are headings; sheets, limit rows, focus radio rows, picker rows and the info icon are at least touch_target_min (48dp).
Contract: row ids are `<value>Row` (or the pre-existing container id: sortByUsageLayout, contactSearchLayout, flSwipeDown, screenTimeLayout); populate functions call bindSwitchRow(on) or bindValueRow(text) after setting the value text; `touch_target_min` lives in values/dimens.xml and BottomSheetMenu rows read it; strip options (maxApps*, alignment*, dateTime*, textSize*, notifications/search) got only minHeight, UX-12 removes them.
Not verified: no device or TalkBack run at all; the items are listed under "UX-5" in docs/RELEASE_CHECKLIST.md; the deprecated announceForAccessibility in AppPickerAdapter is the only announcement path for the cap.
Not verified: the 200% font pass (rows are minHeight, not fixed height, so text should grow them).
Easy to get wrong: the drawer search field's contentDescription is set on the inner search_src_text after the hint, so TalkBack says "Search apps" instead of the rotating example; the daily-wallpaper label still opens the wallpaper URL on touch but is silent to TalkBack (hidden affordance, unchanged); ScreenTimeLimitDialog's limit text is the one tappable node and carries the whole row's description, so Codex's WP24 sizing must keep describe() wired to the picker callback.
Scope: this lands WP30's "tiny value-only tap targets in settings rows" item as a side effect; the rest of WP30 stays open.
