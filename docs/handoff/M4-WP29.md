The home screen's date and battery % refresh while it stays visible: `HomeClockController` registers one receiver for ACTION_DATE_CHANGED, ACTION_TIME_TICK and ACTION_TIMEZONE_CHANGED between the fragment's onResume and onPause; M4-WP11 made ACTION_BATTERY_CHANGED conditional on the status bar being hidden.
Contract: the controller watches `fragment.viewLifecycleOwner` itself via a DefaultLifecycleObserver, so HomeFragment needs no register/unregister call; the receiver guards on `isAdded && view != null` and calls `populateDateTime()`.
Not verified: no device run, so the actual midnight rollover, timezone change and battery-tick refresh were only checked by compile/assemble; BATTERY_CHANGED is sticky and fires on resume when registered (status bar hidden).
Easy to get wrong: the controller must be constructed after the fragment's view exists (it is, in onViewCreated) or `viewLifecycleOwner` throws; registering in the fragment's own onResume instead would duplicate the receiver on a second controller.
