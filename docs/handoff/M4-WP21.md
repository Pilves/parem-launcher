Per-app grayscale: long-press an app and tap "Grayscale" to mark it (`GRAYSCALE_APPS`, CSV, exported); launching a marked app through Parem sets `GRAYSCALE_APP_FG` and the screen goes grey; while Parem is stopped a 1 s `UsageEvents` watch (`GrayscaleController.startAppWatch`) follows recents and notification switches, and `MainActivity.onResume` clears the flag and reconciles.
Contract: the gate `GrayscaleController.appModeReady()` is grant + usage access + Parem is default home, checked before any write of `APP_FG`; the toggle walks the user through each missing condition one tap at a time (grant sheet, then usage access, then set default home) and marks only when all three hold; the watcher skips its query while the screen is off; `GRAYSCALE_APP_FG` is device-only.
Not verified: the battery cost of the tick (the M4-WP11 soak has no recorded result); that `queryEvents` sees a resume within a second; work-profile and Private Space switches, whose events are not in the main user's query (accepted gap: grey stays until the next home press).
Easy to get wrong: the reset must stay in `onResume`, not `onStart`, because a translucent or trampoline launch only pauses Parem; with the gate closed nothing writes `APP_FG`, which is the whole "never stuck grey" argument, so no new code path may write it elsewhere.
