Settings-card sheets were migrated to `Dialog.dismissOnDestroy(viewLifecycleOwner)` (new in `ui/BottomSheetMenu.kt`), so those dialogs close with the fragment view; later source review found the `showLockConsent` route does not attach that hook and needs a separate lifecycle investigation; `populateWellbeingSection`/`resetOpenPickers` return when the binding is gone, `recreate()` goes through `activity?`, the import launcher checks `isAdded`, and settings navigation only fires while Settings is the current destination (fast double-tap).
Contract: ARCHITECTURE.md convention — a sheet opened from a fragment must call `dismissOnDestroy`, because dialogs belong to the activity window, not the fragment.
Not verified: open each sheet, press Home, interact, on a device (the roadmap's done criterion).
Easy to get wrong: a sheet that forgets `dismissOnDestroy` may outlive its fragment view; `GrayscaleSheet` did the same thing its own way before the helper existed.
