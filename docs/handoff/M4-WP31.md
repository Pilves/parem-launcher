Every sheet opened from a Settings card is tied to the fragment with `Dialog.dismissOnDestroy(viewLifecycleOwner)` (new in `ui/BottomSheetMenu.kt`), so Home closes it instead of leaving it over the home screen with callbacks into a detached fragment; `populateWellbeingSection`/`resetOpenPickers` return when the binding is gone, `recreate()` goes through `activity?`, the import launcher checks `isAdded`, and settings navigation only fires while Settings is the current destination (fast double-tap).
Contract: ARCHITECTURE.md convention — a sheet opened from a fragment must call `dismissOnDestroy`, because dialogs belong to the activity window, not the fragment.
Not verified: open each sheet, press Home, interact, on a device (the roadmap's done criterion).
Easy to get wrong: a new sheet that forgets `dismissOnDestroy` reproduces the crash; `GrayscaleSheet` did the same thing its own way before the helper existed.
