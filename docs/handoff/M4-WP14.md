With Parem as default home, drawer search lists app shortcuts (dynamic, manifest, pinned — not cached) under the app results, e.g. "liked" for Spotify's Liked Songs or "incog" for Chrome's New Incognito tab; tap or Enter launches through `LauncherApps` with the same limits, pause and focus rules as the app.
Contract: `helper/ShortcutMatcher.filter(entries, query, limit = 5)` — query of 3+ characters, a single token matches the shortcut label alone, a multi-token query also matches "app label + shortcut label", and the shortcut is dropped when the query matches the app label by itself; `DrawerRows.decorate` places the section (tested); `AppListSource` caches only `Raw` shortcuts keyed on the package stamp plus a shortcut stamp and re-checks host permission before serving (649fbc9).
Not verified: `getShortcuts` on OEM skins and how often `onShortcutsChanged` fires; Chrome manifest shortcuts on the emulator image; `onPackagesAvailable` on Private Space unlock.
Easy to get wrong: auto-launch counts app rows only (DECISIONS: shortcuts surface only when the app word matches 0 or 2+ app rows) — counting shortcut rows would let a chat-name dynamic shortcut suppress an app's auto-launch; private shortcuts must never reach `AppOpenCounter` (exported).
