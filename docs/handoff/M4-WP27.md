Single-match auto-launch in the drawer skips queries that read as a value: a digit-led query of digits/spaces/operators, maths, a unit conversion, a currency conversion or a phone number ("5", "2+2", "5 km in mi", "10 eur in usd", "+372…").
Contract: `OmniboxResolver.blocksAutoLaunch(query): Boolean`, Android-free; `AppDrawerAdapter.autoLaunch` ANDs its negation into the existing condition next to `autoLaunchGuard()`, so the fragment guard lambda is untouched and the check runs on the filter's own constraint string.
Not verified: on a device, that "5" with a single matching app (M365) leaves the drawer open; only the JVM tests cover the predicate.
Easy to get wrong: a query with any letter is an app query again ("1p" for 1Password still auto-launches), so a half-typed conversion like "5 k" is not blocked until it matches `UnitConverter.looksLikeConversion`; Enter still launches the top row regardless.
