Both swipe listeners decide swipes through helper/SwipeThresholds from ViewConfiguration numbers (distance >= max(3 x scaledTouchSlop, 48dp) or velocity >= 4 x scaledMinimumFlingVelocity, off-axis under half on-axis, inside slop is always a tap), and haptics go through helper/Haptics (LONG_PRESS on slot and empty-home long-press, CONFIRM on a recognised letter, REJECT on a rejected letter or a locked-layout refusal, API 29 fallbacks inside).
Contract: SwipeThresholds.classify(dx, dy, vx, vy, touchSlopPx, minFlingVelocityPx, density) returns Direction or null; GestureLetterOverlayView.onLetterDetected now returns Boolean (false = treat as rejected: overlay buzzes REJECT and fades the trail over 150 ms, instantly under skipAnimations()); listener/SwipeConfig.from(context) wraps the ViewConfiguration read; pressed text colour is primaryColorTrans50 via text_colors_default.xml.
Not verified: nothing ran on a device; the UX-3 lines appended to RELEASE_CHECKLIST.md cover slot drift, haptics on/off, letter reject fade and pressed-state clearing. Lint was not run (only compile, unit tests and assembleDebug).
Easy to get wrong: classification still happens inside GestureDetector.onFling, so a drag that stops dead before release (velocity under 1 x minimum fling) is no swipe at any distance; ViewSwipeTouchListener clears isPressed itself once a move passes slop, so do not re-set it in subclasses on ACTION_MOVE; the overlay only treats a stroke as a rejected letter when the path turned (isLetterCandidate), straight strokes stay swipes and get no REJECT.
