One launch path: double-tap "Open app" runs through `HomeGesturesController.executeGestureAction` → `HomeSlotsController.launchApp`; the quiet list wraps `listener.open` in the focus check plus `BadHabitDialogs.gateLaunch` and counts the open; website slots/folders, omnibox web search, "!bang", the no-results search and both search gestures go through `BadHabitDialogs.gateWebOpen`.
Contract: an app launch (anything ending in `startMainActivity`) is `gateLaunch` → `MainViewModel.selectedApp`; a web open always goes to one known app per `WebLaunchTarget.target(handler, candidates, allowed)` — the default handler if there is one (focus-blocked → toast, even if another browser is allowed), otherwise the first focus-allowed candidate stands in for the chooser, null blocks with the focus toast, "" means no app at all; `gateWebOpen` hands that package to `open`, which pins the intent to it (`AppModel.appPackage` → `launchUrl(url, packageName).setPackage`, `openSearch(query, packageName)`), so the limit/pause that ran apply to the browser that receives the intent; the focus toast is `FocusModeManager.showBlocked(context)` everywhere; `DoubleTapActionManager` is storage only (`execute` is gone).
Not verified: any route on a device (focus + limit + pause sheets from double-tap, the quiet list and the omnibox); whether a snoozed notification's `contentIntent` still opens after the pause's coroutine delay; open counts for web opens are not recorded (the browser is not "opened" as an app) and quiet-list opens count only for the personal profile.
Easy to get wrong: without a default browser the system chooser no longer appears for Parem web opens — the first allowed browser is pinned so it can be gated; `gateWebOpen` does its own focus check because `gateLaunch` passes focus-blocked packages straight to `open()` expecting it to toast; `launchUrl`'s own focus resolution is only a backstop for an ungated caller (none exist today); `executeGestureAction` must keep handling `QUIET_LIST` for imported double-tap values.
