One launch path: double-tap "Open app" runs through `HomeGesturesController.executeGestureAction` → `HomeSlotsController.launchApp`; the quiet list wraps `listener.open` in the focus check plus `BadHabitDialogs.gateLaunch` and counts the open; website slots/folders, omnibox web search, "!bang", the no-results search and both search gestures go through `BadHabitDialogs.gateWebOpen`.
Contract: an app launch (anything ending in `startMainActivity`) is `gateLaunch` → `MainViewModel.selectedApp`; a web open is gated per `WebLaunchTarget.target(handler, candidates, allowed?)` — the default handler if there is one (focus-blocked → toast, even if another browser is allowed); with no default and focus off, "" = the system chooser shows and nothing is gated; with no default under focus (`allowed` non-null), the first allowed candidate stands in for the chooser and null blocks with the focus toast; `gateWebOpen` hands that package to `open`, which pins the intent to it (`AppModel.appPackage` → `launchUrl(url, packageName).setPackage`, `openSearch(query, packageName)`), so the limit/pause that ran apply to the browser that receives the intent; the focus toast is `FocusModeManager.showBlocked(context)` everywhere; `DoubleTapActionManager` is storage only (`execute` is gone).
Not verified: any route on a device (focus + limit + pause sheets from double-tap, the quiet list and the omnibox); whether a snoozed notification's `contentIntent` still opens after the pause's coroutine delay; a web open through the chooser (no default browser, focus off) skips the limit/pause of whichever browser the user picks — accepted gap, the receiver is unknown; open counts for web opens are not recorded (the browser is not "opened" as an app) and quiet-list opens count only for the personal profile.
Easy to get wrong: the chooser is replaced by the first allowed browser only while focus is active; with focus off it must keep showing (no pinning, no gate); `gateWebOpen` does its own focus check because `gateLaunch` passes focus-blocked packages straight to `open()` expecting it to toast; `launchUrl`'s own focus resolution is only a backstop for an ungated caller (none exist today); `executeGestureAction` must keep handling `QUIET_LIST` for imported double-tap values.
