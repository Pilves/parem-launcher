Returning to Home from the drawer or Settings re-parents cached widget views from `MainActivity.widgetViews` (`WidgetViewCache`) instead of a views IPC and inflation; the dropped Home tree no longer stays reachable through its host views.
Contract: a view is reused only for the same ID, provider@profile signature, package stamp and application configuration, outside a forced pass, and only if it never showed the error view; `appWidgetHost.deleteAppWidgetId` evicts, so every delete must go through it.
Supersedes M6-WP58's per-controller sweep: orphan IDs are swept on each activity's first scan and on forced scans, not on every return from the drawer or Settings; the M6-WP53 availability check still runs on every pass.
Each widget's size is reported once per pass from `resizeWidgetWrappers` and skipped when unchanged.
Not verified on a device: the Perfetto and heap checks, rotation, dark-mode flips, provider updates and configure-cancel; collection widgets now keep their scroll position across drawer visits (PO decision).
