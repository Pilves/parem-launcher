Parem rotates freely from sw600dp up and stays portrait on phones (`bool/lock_portrait`, false in `values-sw600dp`); `MainActivity` sets `UNSPECIFIED` explicitly so a fold/unfold recreate can't keep a stale lock; settings and the drawer cap their reading width with `dimen/content_side_padding` stepped at w600 (64dp), w840 (200dp), w1200 (360dp) and w1600 (520dp); the smoke matrix gained foldable and tablet legs plus `rotatesOnLargeScreenOnly`.
Contract: the 7-inch `isTablet()` is gone; no `configChanges` for size or orientation, so a resize recreates the activity (and re-runs `restoreWidgets()`, trap #2); table-top posture is deferred to 6.1 and split screen / desktop window are manual checks (DECISIONS.md).
Not verified: anything on a real foldable or tablet (table-top, split screen, desktop window); that `requestedOrientation` survives `recreate()` on API ≤ 35.
Easy to get wrong: `sw600dp`/`w<N>dp` follow the window while Android 16's ignore rule follows the display, so a narrow split half on a tablet asks for portrait and is ignored; phone landscape stays unsupported by product decision.
