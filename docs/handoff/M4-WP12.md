First run (and once for updating users, `Constants.ONBOARDING_VERSION = 3`) is two screens: "Set as home screen" (role request; a second tap opens the system home-app settings if the dialog doesn't come back) and an optional Calm setup with five skippable rows — screen time, slow down an app (mindful pause), quiet notifications, double tap to lock, grayscale; the feature tour and `OnboardingPagerAdapter` are gone.
Contract: each Calm row calls the owning package's entry point (M4-WP1/2/5, M2-WP5); the footer reads "Change any of these later in Settings" rather than naming a section; the screen has five rows, not the design table's four, because screen time is a prerequisite for Slow down.
Not verified: the ≥90% "set as home" target needs a closed test that has not run; ROLE_HOME re-prompting after a denial on OEM ROMs; the bounce into Default-apps settings after `RESULT_OK` was removed but not device-checked.
Easy to get wrong: accepting the lock row sets double tap to LOCK_SCREEN before the service is on — backing out of Accessibility settings loses the previous action and the next double tap lands in M2-WP5's consent; the onboarding lock consent offers no device-admin route, so sideloaded Android 13+ with a greyed restricted-settings switch needs a follow-up or a device check.
