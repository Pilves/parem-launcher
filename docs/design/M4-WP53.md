# M4-WP53 — One app menu everywhere (design, UX-13)

Status: revised proposal, 2026-10-15, checked against `next` at `950cdcb`.
**Awaiting Patric's approval; no product code changed.** This replaces the earlier
WP53 draft, retaining its shared sheet, home menu and Undo direction. It does
not approve or implement the separate WP49/50/51 or UX-REDESIGN proposals.

Reading this as a native Android launcher redesign: quiet typography, explicit
actions and quick, restrained motion. Apply Ponytail's existing-helper-first
rule and the taste/Emil motion principles to Views/Kotlin. Keep `BottomSheetMenu`,
AppCompat and Material 1.12; no new UI framework or dependency.

## Audit and recommended direction

| Before | After | Why / owner |
|---|---|---|
| Drawer long-press replaces the app name with six small actions and Close (`AppDrawerAdapter.bind`, `adapter_app_drawer.xml`). | A sheet titled with the app name; every action is a full text row. | Keep context visible; WP53. |
| Home has an untitled, differently ordered menu and ambiguous “Delete”. | Shared app rows, then a clearly labelled Home slot group, then “Remove from home”. | Predictable order without removing useful slot actions; WP53. |
| Home has Add website and Create folder on occupied slots; the earlier draft removed them. | Retain both, alongside Change app. | No remove-first workaround or extra “More” sheet; WP53. |
| Removal is immediate; locked home responds with a toast. | Undo for removal; “Home layout is locked” with Unlock. | Offer recovery and the fix; WP53. |
| Background long-press offers only Add widget and Settings in a separate dialog. | All apps, Notifications, Add widget, Wallpaper, Settings through the shared builder. | A discoverable home hub; WP53. |
| Drawer Rename is package-scoped; home labels are independent. The earlier draft proposed synchronising every slot with that package. | Keep local home names; constrain legacy drawer aliases to the personal profile. | Avoid renaming unrelated profiles or custom slot labels; WP53, minimal profile-safety extension below. |
| Sheets use 14sp dim titles / hard-coded body sizes and have no checked-row API. | DESIGN Title/Body/Caption, clear state and one scroller. | Shared builder work belongs to WP52, using WP50 tokens. |
| Settings scatter search controls and expand inline strips. | The six-section structure and checked choice sheets in WP51. | Keep this proposal focused; no settings rebuild here. |
| Drawer entrance scales text from 110%; navigation still uses view Animations. | Remove text scaling and adopt seekable navigation Animators through WP55. | Motion audit: block these effects from being copied into new menus; WP55 owns their correction. |

Fresh home's four “App” labels belong to WP49. QA's “1 minutes” graph copy
belongs to WP48. Neither is silently bundled here. The device QA in
`/tmp/parem-qa/results.txt` verifies existing Android 16 flows, not this design.

## Concrete menu layouts

Wireframes show order and grouping, not fixed heights. The long home menu has
one scroll area; all rows remain reachable at large text sizes.

```text
DRAWER — personal Spotify       HOME SLOT — personal Spotify
────────────────────────       ────────────────────────────
          ━                               ━
Spotify                        Spotify
App info                       App info
Rename                         Rename
Time limit                     Time limit
  30 min                         30 min
Mindful pause   ✓               Mindful pause   ✓
Grayscale                      Grayscale
  Off                            Off
Hide from app list             Hide from app list
                                 App stays on home
                               [24dp group gap]
                               Home slot
                               Change app
                               Add website…
                               Create folder
[24dp group gap]                [24dp group gap]
Uninstall                      Remove from home
```

```text
HOME BACKGROUND                RENAME FROM HOME
────────────────────────       ────────────────────────────
          ━                               ━
Home                           Rename on home
All apps                       Name
Notifications                  [ Spotify                 ]
Add widget                     Save
Wallpaper
Settings                       Back/swipe away: no change
```

The common app rows always keep this order: **App info → Rename → Time limit →
Mindful pause → Grayscale → Hide from app list**. Then, on home only, a
`section_gap`, Caption heading **Home slot**, **Change app → Add website… →
Create folder**. A final `section_gap` precedes the destructive row.

- **App info** targets the selected `AppModel.user` and package.
- **Rename** opens the input sheet described below. Both contexts expose the
  same action; their rename sheets explicitly name where the label changes.
- **Time limit**, summary **None / 30 min / 1 h / …**, always opens the existing
  usage-access-gated picker. It never removes a limit on the initial tap.
  Editing/removing an existing limit and checked duration rows require WP47's
  picker amendment from `UX-REDESIGN-6.0.md` §3.7; WP53 does not rewrite the picker.
- **Mindful pause** appears only with a limit, matching the current helper;
  checked means on. Tap flips it and closes the sheet, following the builder's
  existing action contract. Pause without a limit is WP47's decision.
- **Grayscale**, summary **Off / On / Set up**, keeps the existing grant flow.
  Set up means unmarked and prerequisites missing; a stored mark is shown On.
- **Hide from app list** keeps a home slot intact; its home-only Caption says
  **App stays on home**. Hidden-list rows instead say **Show in app list**.
- **Uninstall** exists only for uninstallable personal-profile apps and invokes
  Android's uninstall UI. Other profiles use App info; omit Uninstall there and
  on system apps rather than presenting an action that cannot do what it says.
- **Remove from home** clears this slot, never uninstalls the app. No “Delete”
  label, separate close button, new colour or icon-only action.

## Applicability and rename contract

| Context | Rows / exceptions |
|---|---|
| Personal app in drawer or on home | Common rows above. Home gets its slot group and Remove from home; drawer gets Uninstall when supported. |
| Hidden-apps list | App info → Show in app list → gap → Uninstall when supported. Preserve the current restricted hidden-list menu. |
| Work app | App info and Hide/Show in app list. Home additionally offers local Rename, its slot group and Remove from home. Omit package-scoped limits, mindful pause, grayscale and drawer Rename. |
| Private app | App info only. Preserve private-space header and shortcut-row behaviour: neither opens an app menu. Private apps remain excluded from slot pickers. |
| Website slot | Title = site label; Rename → Change app → Add website… → Create folder → gap → Remove from home. Add website replaces only after Save; cancellation keeps the original. |
| Folder slot | Title = folder name; Change app → Add website… → Create folder → gap → Remove folder from home. Create folder summary: “Replaces this folder after saving”. No invented folder editor. |
| Empty slot | Title “Add to home”; Select app → Add website… → Create folder. No removal row. Empty-slot tap/hint changes stay with WP49. |

The current drawer does offer limits/grayscale/rename for work apps; omitting
those is a proposed safety correction, not an assertion about existing code.
Their stores identify apps by package and cannot safely distinguish the work
and personal copies. No new profile-aware settings schema is introduced.

**Home Rename** edits only this slot's `HOME_APP_NAME`, for an app or website.
The sheet title is **Rename on home**. **Drawer Rename** edits only the existing
personal drawer alias `RENAME_<pkg>`; title **Rename in app list**. It does not
rewrite slots, folders, gesture labels or a work/private copy. The selection
flow's existing header Rename remains a slot-only operation (flags 1–8).

The input is prefilled and selected, has a visible label **Name**, and uses
IME Done and **Save** through the same handler. Blank/whitespace input keeps
the sheet open with inline error **Enter a name**; Back/swipe discards edits.
Names are stored as entered after trimming and wrapped for bidirectional
presentation, not stored with formatting controls added by the UI.

Required minimal extension: change `AppListRebuilder`'s rename callback from
`(package) -> alias` to `(package, user) -> alias`; `AppListSource` supplies an
empty alias outside `Process.myUserHandle()`. Keep all existing keys, raw app
caching and package-change stamps. Add one existing-suite regression test with
the same package in personal/work/private profiles: only the personal label
changes. This fixes the existing read leak without a migration.

## Shared visual and motion contract

Use [DESIGN.md](DESIGN.md) §3–8, as resources supplied by WP50/52:

| Role | Exact value / behaviour |
|---|---|
| Title | `TextAppearance.Parem.Title`: 28sp phone / 32sp sw600dp, primary colour, mainFontFamily, accessibility heading. |
| Actions and input | Body: 18sp / 20sp, regular, 24sp line height. Save uses Label, 16sp. |
| Summaries and group label | Caption: 14sp, 20sp line height, `primaryColorTrans80`; no essential text at Trans50. |
| Rows | Whole width tappable, `minHeight = touch_target_min` 48dp; `row_padding_vertical` 14dp each side. Height grows with text. |
| Spacing | `sheet_padding_horizontal` 24dp (32dp landscape tablet); `space_xs` 4dp between label and summary; `section_gap` 24dp (32dp tablet). |
| Surface | Solid `primaryInverseColor`, primary text, `corner_surface` 16dp; existing 40×4dp handle is decorative. No wallpaper shadow inside sheets. |
| Width | Full available phone width capped at `sheet_max_width` 640dp; 480dp on sw600dp-w840dp. Centred; open expanded, skip collapsed. |
| Press and state | Pressed colour immediately; no text scale. Checked/state updates are immediate, with no row stagger or animated relayout. |
| Sheet motion target | Shared window entrance 200ms (`motion_medium`, `linear_out_slow_in`); exit 150ms (`motion_short`, `fast_out_linear_in`). Slide as one surface, no child animations. These are WP52's shared-frame acceptance targets, not new per-menu animators in WP53. |
| Navigation | Existing routes; WP55 owns 200ms `fast_out_slow_in` navigation entrance / 150ms `fast_out_linear_in` exit and predictive-back seeking. |

Retain Material's drag/settle implementation. Never add another translation
animator over `BottomSheetBehavior`. Close the current sheet before opening an
input/picker/system surface; do not stack sheets or add a delayed callback to
sequence an animation. Repeated long-press opens at most one app menu. Dismissal
wins over an opening animation; stale callbacks cannot reopen it. Any explicit
animator must cancel/retarget from the current state, and never animate layout
height or scale text.

`skipAnimations()` is authoritative: on e-ink **or any system scale at zero**,
finish immediately, including exit and feedback motion. No fade fallback when
Remove animations is on. Android has no separate reduced-motion preference in
this app; do not invent a pref or infer one from a nonzero scale. Keep pressed
colour and native state announcements. E-ink uses WP52's plain pressed drawable
instead of ripple. Preserve `disableAnimationsOnEink()` and reuse `Haptics`:
one LONG_PRESS for opening, REJECT for the locked refusal; taps add no vibration.

## Recovery, lifecycle and accessibility

Use Material `Snackbar` already installed: **“%1$s removed from home” · Undo**,
**“Folder removed from home” · Undo**, **“Home layout is locked” · Unlock**.
Unlock changes the pref but launches nothing; the next edit works. Bidi-wrap
names in messages. Inherit root insets, theme the bar with Parem colours, allow
its text/action to wrap at 200%, and let accessibility extend its timeout.
Do not add a custom Snackbar implementation in anticipation of a theme issue.

Capture one immutable `SlotSnapshot`: all five home fields (name, package,
activity, user, URL), all four swipe-up fields, and a copied `FolderGroup` with
its app list. Controller-local functions read/write it using existing `Prefs`,
`SwipeUpAppManager`, `FolderManager`. No `SlotStore` interface, fake map store,
repository or persistence format. Removal clears all those slot fields. Undo
restores only that slot and folder, preserving unrelated slots.

One pending removal at a time: a later removal supersedes it. A committed edit
or view destruction dismisses and invalidates the pending Undo. Guard Undo
against current state differing from the captured post-removal state, so it
cannot overwrite newer data. A small pure restoration decision alongside the
snapshot can be JVM-tested for app, website, folder, swipe-up data, unrelated
slot preservation and stale-state rejection; actual Prefs adapters still need
the device round-trip. Process death need not preserve pending Undo.

Every sheet is tied to `viewLifecycleOwner` with `dismissOnDestroy`; posted or
async work checks attachment/binding. Rename's input must remain above the IME.
Whole rows expose label, button/toggle role and current state once; decorative
checks/handle are hidden from traversal. Keyboard/D-pad and TalkBack can open,
operate and dismiss menus; focus returns to the invoking row if it survives,
or the nearest remaining row after removal. At 200% fonts, titles and summaries
wrap, nothing ellipsizes critical actions, and the final removal row is reached
through the single scroller. RTL uses start/end padding and wrapped app labels.
The invisible lock view, widget IDs and launch/selection routing stay intact.

## Smallest implementation sequence and verification

1. Approve this direction and local rename contract. WP25's expanded-home fix
   and WP30 land independently. WP50 provides tokens, WP51 owns settings, WP52
   then provides the shared frame/check/summary API. Honour that existing chain;
   do not create a WP51/WP52 dependency cycle in this package.
2. WP53: one `ui/AppMenu.kt` function called from drawer and home, with ordinary
   callbacks and a context/slot parameter. Adapter reports long-press; fragment
   owns actions. Reuse existing app-info, hide, limit and grayscale functions.
   Apply the narrow profile callback change above and local rename input.
3. Keep the existing home replacement routes; add snapshot/Undo and Unlock.
   Rebuild background menu in `BottomSheetMenu`: All apps uses the launch-drawer
   route; Notifications reuses the existing notification action; Add widget uses
   the existing picker; Wallpaper opens the Android wallpaper intent with its
   existing unavailable-handler pattern; Settings uses existing navigation.
4. Remove drawer strip/inline rename views and `dialog_home_menu.xml`. Delete
   drawables only after checking references; keep `ic_check` for WP52. Strings
   are resources appended as non-translatable; add Unreleased behaviour notes.

Implementation ownership: roadmap WP53's adapter/layout, drawer fragment, home
slots/gestures, home menu deletion, unused drawables and strings; new AppMenu
and pure snapshot plus tests. Named scope extension: `AppListSource.kt`,
`AppListRebuilder.kt`, its existing test for personal-only aliases. WP47 owns
limit-picker editing; WP50/51/52/55 keep their own files. No `MainActivity`,
lock path, widget bookkeeping, Prefs migration or generated handoff change.

Before calling implementation done: AGENTS Gradle compile/unit/assemble checks,
handoff harness tests, snapshot/identity regressions, then phone/tablet checks
in light/dark, portrait/landscape, 200% font and animations off. Verify each menu
row, system/work/private applicability, rename cancellation/IME, removal → Undo
including folder/swipe data, stale Undo, Home while a sheet is open, and actual
TalkBack/D-pad focus and Snackbar reachability. E-ink remains explicitly
unverified if no device is available, following DECISIONS.md.

This revision is documentation only: no APK, device behaviour, motion timing,
contrast or accessibility pass was performed. It closes no work package and
must not produce a completion fragment or generated roadmap changes.
