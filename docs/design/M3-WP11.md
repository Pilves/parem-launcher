# M3-WP11 — Opt-in crash reports (no network SDK)

Status: proposal (design first, awaiting Patric).

## Problem

Parem cannot see crashes from GitHub, IzzyOnDroid or F-Droid installs. Roadmap: off by default and nothing collected; when on, the user sees and sends the report. There is no `Application` subclass or `android:process` today; activity, accessibility service and WorkManager share one process.

## Options

**A. ACRA 5.14.2 (latest, 2026-10-01) with `acra-mail` (or a share sender) and `acra-dialog`.** On Maven the AARs are core 294 KB, mail 24 KB and dialog 35 KB. It needs an `Application` that calls `initAcra` in `attachBaseContext` (https://www.acra.ch/docs/Setup). **Trap:** the `acra-core-5.14.2.pom` declares `kotlin-stdlib 2.4.20`, but Parem is on Kotlin 2.1.20. That forces a Kotlin bump or pinning an older ACRA.

**B. Our own handler, about 80 lines, no dependencies.** `Thread.setDefaultUncaughtExceptionHandler` covers every thread that has no handler of its own (https://developer.android.com/reference/java/lang/Thread#setDefaultUncaughtExceptionHandler(java.lang.Thread.UncaughtExceptionHandler)). It writes a text report, then chains to the previous handler, so the system dialog and Play vitals still see the crash. Parem is HOME, so the OS relaunches it right away. On that relaunch a BottomSheetMenu offers the report through `ACTION_SEND`.

**C. `ApplicationExitInfo` only (API 30+).** Rejected. `getTraceInputStream()` is "typically available when the reason is REASON_ANR", plus native tombstones from API 31. It gives no Java stack for `REASON_CRASH` (https://developer.android.com/reference/android/app/ApplicationExitInfo).

## Recommendation

**B.** It adds no dependency and no Kotlin bump, and the user sees every byte. F-Droid only flags "sending crash reports without your knowledge or permission" (https://f-droid.org/docs/Anti-Features/). An opt-in plus a share the user sends is clean. Play vitals keeps covering the Play channel (https://developer.android.com/topic/performance/vitals/crash), because the handler chains to the default one.

## Exact scope

| File | Change |
|---|---|
| `ParemApp.kt` (new `Application`) + manifest `android:name` | `onCreate`: `CrashReporter.install(this)` |
| `helper/CrashReportFormatter.kt` (Android-free `object`) | `format(throwable, versionName, versionCode, sdkInt, manufacturer, model, threadName, timeMs)`: a header plus `stackTraceToString()` (the cause chain), capped at 64 KB and cut on a line boundary. No prefs, app lists, logcat or contacts |
| `helper/CrashReporter.kt` | The handler checks `prefs.crashReportsEnabled`. When it is off, it delegates immediately and writes nothing. When it is on, it writes `File(noBackupFilesDir, "crash.txt")`. In both cases it **always** calls `previous.uncaughtException`, and the whole body sits in `try/catch(Throwable)`. Also `pending(ctx)` and `clear(ctx)` |
| `data/Prefs.kt` | `crashReportsEnabled` (key `CRASH_REPORTS_ENABLED`, a Boolean, default false). Boolean prefs import safely, so it exports normally |
| `MainActivity.kt` | After `setContentView`, if a report is pending, show the sheet once. Delete the file on any action or on dismiss |
| Sheet (BottomSheetMenu) | "Parem crashed last time". **Send** builds a `createChooser(ACTION_SEND)` with `text/plain`, `EXTRA_SUBJECT`, `EXTRA_TEXT` and `EXTRA_EMAIL`. **Copy** puts the report on the clipboard. **Discard** deletes it |
| `data/Constants.kt` | `CRASH_REPORT_EMAIL`. **Patric supplies the address.** If it is empty, omit `EXTRA_EMAIL` |
| `AppInfoSettingsCard.kt`, `layout/` **and** `layout-land/fragment_settings.xml` | A "Crash reports: off/on" row next to github/privacy that follows the `contactSearchToggle` pattern. It goes in both layouts so the binding is not nullable |
| `strings.xml` | About 6 strings, `translatable="false"` |
| `CrashReportFormatterTest.kt`, `CHANGELOG.md` | Tests and an `[Unreleased]` line |
| M2-WP3 privacy text | One line: crash reports are opt-in and are sent by the user through their own app |

No new permissions, no FileProvider (the report goes inline as text) and no network.

## Done criteria

- `compileDebugKotlin`, `testDebugUnitTest` and `assembleDebug` all exit 0.
- **Off** (the default): a forced crash leaves no file and shows no sheet.
- **On**: the system "stopped" dialog appears as before. After the relaunch there is exactly one sheet, and Send opens the chooser with the report in the body.
- The release APK grows by less than 20 KB.

## Risks & traps

- **Always chain to the previous handler.** If the handler swallows the crash, Play vitals stops counting it and the process is left half-dead.
- **Install the handler in `Application`, not `MainActivity`.** Otherwise crashes in the accessibility service or in workers are missed. ContentProvider initializers (WorkManager's androidx.startup) run before `Application.onCreate`, so a crash in them is not captured. That is acceptable.
- **A crash may be the first prefs read.** Then the handler does a disk read on a dying thread. That is why the whole body sits in the catch-all.
- **Binder limit.** Intent extras go through a 1 MB transaction buffer (https://developer.android.com/reference/android/os/TransactionTooLargeException). The 64 KB cap keeps the report well under it.
- **Startup crash loop.** Parem can crash before the sheet shows. The file then waits for the next good start, and the sheet still shows only once.
- **Exception messages can hold user text** (e.g. an omnibox query); the user sees it all before sending.

## Test plan

- JVM: the formatter includes the cause chain and the header. Output is at most 64 KB and never cut mid-line. A null message is safe.
- Device (debug build only): add a temporary crash trigger and do not ship it. With the setting off, confirm no file and no sheet. With it on, confirm the sheet and that Send, Copy and Discard each work and remove the file. Repeat on a background thread (the weather worker).

## Not verified

- Whether Kotlin 2.1.20 can build against ACRA 5.14.2 (stdlib 2.4.20). This is inferred from the POM. Moot if B is chosen.
- How chaining and the HOME relaunch behave on Android 15–16 OEM skins. Device pass needed.
- The size delta after R8. It is an estimate.
