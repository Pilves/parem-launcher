## Known accepted limitation

With no default browser and Focus off, the system chooser is untouched; the chosen browser bypasses browser-specific app-limit/mindful-pause checks. Under Focus, the first allowed browser is selected or the open is blocked. This is the previously accepted gap, not a regression fixed in this release.

## Settings retention across upgrades

Tablet checks used isolated packages with the same package identity and debug
signing key on both sides of each update; the user's installed release app was
not replaced. Shipping updates must likewise retain `com.parem.launcher` and the
existing release signing key. Install over the old APK; uninstalling or clearing
storage is not an upgrade and deletes local settings.

- Published v5.5.1 (101) → beta.2 (104): all 33 existing preference entries were
  identical immediately after installation and after first launch. The fixture
  exercised theme, text size, alignment, gestures, home slot, folder, hidden apps,
  Focus whitelist and app limits. Home displayed Settings and the Tools folder.
  The only new entry was an empty `WIDGET_IDS`, created by existing migration.
- v5.7.0 (102) → beta.2 (104): all existing preferences survived, and all four
  bound Calendar, Weather, Notes and Clock widgets rendered after updating.
- Settings UI export to Downloads and re-import: the complete preference map
  matched the pre-export map, including device-local widget bindings.
- Evidence: `/home/pi/parem-qa/beta2/old-upgrade-result.json`, its before/after XML
  snapshots, `upgrade-window.png`, `prefs-after-ui-import.xml` and the earlier
  QA upgrade captures. These are representative upgrades, not every old version.

Older Olauncher-branded tags (including v4.3.5, v5.0.0 and v5.3.8) used package
`app.olauncher`. Android treats Parem as a separate app from those versions;
this is not an in-place update, and automatic retention across that package
change is not established by these checks. Do not advertise it as such.

Owner confirmed the spoken TalkBack home checks (first focus avoids the lock
view; All apps opens) and double-tap locking. The isolated QA package needed an
external accessibility package-filter override; production package filters and
the lock path were unchanged. Three Android state tests passed: preference
export/import, Focus expiry/schedule pause, and actual WorkManager theme-worker
execution. Original accessibility services and QA preferences were restored.
